# PDF-отчёт для руководителя и аналитика

Этап 16 формирует русскоязычный PDF из агрегатов выбранного запуска разметки. DataLens для генерации не нужен.
Перед использованием примените миграции до `e1f2a3b4c5d6`, загрузите и сверьте исходный snapshot и разметку.

## Установка и запуск

```bash
.venv/bin/python -m pip install -e '.[reporting]'
.venv/bin/python scripts/generate_analytical_report.py 1 data/reports/management-run-1
```

`1` — числовой ID из `analytics.problem_runs`. Подключение задаётся через `POSTGRES_*` в `.env`.
В Linux по умолчанию используется `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`.
При отсутствии шрифта установите DejaVu Sans или передайте `--font /path/to/cyrillic-font.ttf`.
Шрифт должен разрешать встраивание в PDF и содержать кириллицу. Он не копируется в репозиторий.
На Windows, macOS и в контейнере укажите доступный TTF явно. Обычный Docker-образ проекта не содержит
reporting-extra и шрифты: их нужно установить отдельно для генерации отчёта.

В новой папке появятся:

- `report.pdf` — переносимый PDF со встроенным шрифтом и векторными графиками;
- `report.json` — все использованные агрегаты и рекомендации, включая не поместившиеся в краткую PDF-версию;
- `manifest.json` — привязка к запуску и dataset, SHA-256 PDF, JSON и шрифта, версия ReportLab.

Повторная запись в существующую папку запрещена. При ошибке незавершённый отчёт не публикуется.
Эти файлы содержат аналитические сведения об организациях: храните их в игнорируемой `data/reports`,
передавайте только согласованной аудитории. Публичная публикация не выполняется.

## Содержание

1. Источник, период и идентификаторы; объём отзывов, число клиник, взвешенный рейтинг, доля оценок 1–3.
2. Отдельные графики жалоб, сильных сторон и смешанных оценок по категориям.
3. Таблица 20 клиник с наибольшим объёмом отзывов, показатели достаточности выборки, месячные таблицы.
4. Первые 10 рекомендаций этапа 13: очередь проверки, объяснение балла, статус необходимости ручного анализа.
5. Числа принятых, предварительных и отклонённых оценок, версии правил/таксономии, ограничения и происхождение.

Загрузка выполняется в одной PostgreSQL-транзакции `REPEATABLE READ, READ ONLY`. Числа по организациям
и месяцам сверяются с размером dataset; знаменатель каждой категории должен охватывать весь dataset.
Среднее рейтингов клиник не используется — суммируются баллы рейтингов и делятся на общее число отзывов.
Предварительные жалобы остаются видны отдельно от принятых; rejected не увеличивают графики сигналов.

Тексты отзывов, авторы, координаты доказательств и ID отдельных отзывов в PDF/JSON не включаются.
Наименования организаций экранируются перед вставкой в PDF-разметку. Пустые месяцы не заполняются нулями.
Числа по категориям нельзя суммировать как уникальные жалобы: разметка многометочная.
Порог 30 не гарантирует статистической точности. Сигналы отражают восприятие пациентов и не подтверждают
медицинские ошибки, причинность, финансовый ущерб или окупаемость.

Тесты PDF выполняются при установленном reporting-extra. Дополнительно проверяется извлечение кириллицы
через `pdftotext` при наличии этой программы. PostgreSQL-тесты требуют отдельной `TEST_DATABASE_URL`.

Основа PDF-рендеринга: [ReportLab Platypus](https://docs.reportlab.com/reportlab/userguide/ch5_platypus/)
и [встраивание TTF](https://docs.reportlab.com/reportlab/userguide/ch3_fonts/).
