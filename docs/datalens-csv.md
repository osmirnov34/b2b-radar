# Бесплатная демонстрация: локальная PostgreSQL → CSV → DataLens

Облачная БД не требуется. Обработка и PostgreSQL остаются локальными; в DataLens вручную загружаются
четыре агрегатные таблицы. Файлы не содержат текстов отзывов, авторов, идентификаторов отзывов, доказательств
или паролей. Названия и ID клиник присутствуют: это агрегаты по организациям, не обезличенная публичная статистика.
Не включайте публичный доступ без отдельной проверки. Для первого просмотра используйте свой аккаунт.

## 1. Готовая выгрузка

Для текущего отчёта (`dataset_id=1`, `problem_run_id=2`, папка запуска `acceptance-003`) готовый итоговый пакет:

```text
data/reports/datalens-csv-run-2-v2/
  organization_overview.csv    720 строк: клиники и общие KPI
  organization_monthly.csv     14 540 строк: клиники по месяцам
  category_overview.csv        7 200 строк: клиники × 10 категорий
  category_monthly.csv         145 400 строк: клиники × категории × месяцы
  dashboard.json              спецификация графиков и формул, не файл импорта
  manifest.json               контрольные суммы, ID и статус сверки с PDF
  README.md
```

Количество строк не равно количеству отзывов. На текущем датасете отзывов 21 630.
Категории повторяют знаменатель для каждой категории: их нельзя суммировать в общий объём.

## 2. Создайте файловое подключение

1. Откройте свой воркбук DataLens.
2. Выберите «Создать» → «Подключение» → «Файлы» (раздел «Файлы и сервисы»).
3. Нажмите «Загрузить файлы» и выберите **только четыре CSV** из папки выше.
   Не загружайте исходный `reviews.jsonl`, приватные папки запуска, `.env` или JSON отчёта.
4. Для каждого CSV укажите кодировку `utf-8-sig`, разделитель «Запятая», заголовок столбцов «Да».
5. Проверьте русские названия и разбиение столбцов в предпросмотре. Предпросмотр показывает лишь первые
   30 строк, это не размер всей таблицы.
6. Сохраните подключение под именем `dentistry-csv-run-2` в своём воркбуке.

Эта последовательность и ограничения файлов проверены по
[официальной инструкции DataLens](https://yandex.cloud/ru/docs/datalens/operations/connection/create-file).

## 3. Четыре отдельных датасета

Создайте датасеты по одному на CSV, с теми же именами без расширения. Не перетаскивайте все таблицы
на один холст и не создавайте JOIN: это размножит счётчики.

Проверьте типы полей вручную, даже если DataLens распознал их автоматически:

| Поля | Тип и настройка |
|---|---|
| organization_id, category_id | Строка, измерение; не преобразовывать ID в числа |
| organization_name, category_name_ru | Строка, измерение |
| run_id, dataset_id | Целое, измерение; не суммировать |
| month | Дата |
| sample_sufficient, category_active | Логический |
| поля с окончанием `_count` | Целое, для метрик использовать SUM |
| rating_sum, low_rating_count | Дробное число; low_rating_count может содержать погрешность вычисления SQL |

Числа записаны с десятичной точкой, даты — `YYYY-MM-DD`. Потенциальные формулы электронных таблиц
в текстовых ячейках экранируются начальным апострофом; он может быть виден в необычном названии клиники.

## 4. Первый экран: три показателя и жалобы

В датасете `organization_overview` создайте вычисляемые поля:

```text
reviews = SUM([feedback_count])
average_rating = SUM([rating_sum]) / SUM([feedback_count])
low_rating_share = SUM([low_rating_count]) / SUM([feedback_count])
```

Имя поля задаётся отдельно, в редактор формулы вставляется только правая часть после `=`.
Для каждого поля создайте чарт типа «Индикатор». Рейтинг форматируйте с двумя знаками после запятой,
долю — как процент. Без фильтров должны получиться 21 630 отзывов, рейтинг 2,00 и около 79,0% оценок 1–3.

В `category_overview` создайте:

```text
complaint_share = SUM([complaint_count]) / SUM([feedback_count])
```

Создайте горизонтальную столбчатую диаграмму: категория `category_name_ru`, показатель `complaint_share`,
сортировка по доле убыванию. Сохраняйте `category_id` в детализации/группировке, особенно при изменении
таксономии. В текущем наборе названия десяти категорий различны. Для «Цена и расчёты» ожидается
4 063 / 21 630 ≈ 18,8%. Не используйте общий индикатор доли жалоб без группировки по категории.

Откройте свой дашборд и добавьте эти четыре чарта. Сохраните: это первый демонстрационный экран.

## 5. Полный дашборд

Остальные восемь графиков и формулы перечислены в `dashboard.json` и в
[общей инструкции](datalens-dashboard.md#размещение-графиков). Для CSV отличается только источник:
используется загруженная таблица вместо SQL-подзапроса. Схемы полей сохранены.

Добавьте сравнение клиник, сильные стороны, mixed, статус проверки жалоб, динамику рейтинга и объёма,
динамику категорий и число отклонённых оценок. Не усредняйте средние рейтинги клиник — используйте
взвешенную формулу выше. Фильтр клиник связывайте по `organization_id`, не по названию.
Фильтр категорий действует только на category_*; месяцы — только на месячные графики.
По умолчанию не скрывайте малые выборки: порог достаточности — 30 отзывов на соответствующем уровне.

Рядом с KPI подпишите: «Обзорные показатели — весь период запуска. Выборка отзывов может быть смещена.
Разметка предварительная и требует проверки; показатели не измеряют финансовые потери и не доказывают
медицинскую ошибку». Для текущего режима `rules_only` не представляйте жалобы как вручную подтверждённые.

## 6. Обновление без повторного обучения

Для той же локальной демо-базы создавайте пакет всегда в новой папке:

```bash
.venv/bin/python scripts/export_datalens_csv.py \
  data/demo/analytics-local/runs/acceptance-003/08-pdf/report \
  data/reports/datalens-csv-run-2-next \
  --demo-directory data/demo/analytics-local
```

Без `--demo-directory` используются обычные `POSTGRES_*` проекта. Нужны права SELECT на BI-витрины.
Экспортёр проверяет контрольные суммы сохранённых JSON/PDF, фиксирует один read-only repeatable-read snapshot,
сверяет клиники, категории, знаменатели, месяцы и сигналы с PDF. Несовпадение блокирует публикацию.
Пакет готов только при наличии `manifest.json` со статусом `reconciled_with_saved_report`.
Выгрузка не меняет оценки, checkpoint, PDF и код пайплайна; повторное обучение не требуется.

Для этой массовой операции `enable_mergejoin=off` и тайм-аут SQL 60 секунд задаются только через
`SET LOCAL` внутри транзакции: настройки сервера и следующих транзакций не изменяются.
Файлы ограничены 190 MiB каждый (консервативно ниже лимита DataLens), выходная папка — 0700.
Экспорт хранит агрегатные строки в памяти; для существенно больших датасетов потребуется потоковая реализация.

После загрузки нового исследования обновляйте все четыре файла согласованно через «Заменить» в подключении.
Во время последовательной замены файлов дашборд может временно смешивать версии: не демонстрируйте его,
пока все файлы не обновлены и не проверены. Для безопасного отката сохраняйте старую папку CSV;
для изолированного сравнения создавайте новое подключение/датасеты.

## 7. Приёмка и оставшиеся ручные действия

- Сверьте три KPI и долю категории с PDF без активных фильтров.
- Проверьте клинику с малой выборкой, фильтр клиник и отсутствие умножения чисел при фильтрации категорий.
- Проверьте, что пустой месяц не представлен как нулевая доля жалоб без отзывов.
- Не публикуйте тексты, авторов и исходные файлы; не включайте публичные ссылки автоматически.
- Отдельно проверьте качество разметки на выборке отзывов: совпадение CSV/PDF проверяет числа, не истинность выводов.

Вход в ваш аккаунт, загрузка файлов и сборка чартов выполняются вами. Сам код экспорта ничего
не отправляет в DataLens и не создаёт платных ресурсов.
